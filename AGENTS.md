# AGENTS.md

## What Is This

Dictum is a native macOS menu bar app for Polish voice dictation.

Pipeline: microphone → WhisperKit STT → optional MLX LLM cleanup → auto-paste. Everything runs
on-device except HuggingFace model queries in `HuggingFaceModelSearch`.

## Build

- Requires Xcode 26+, macOS 26.0 deployment target, Apple Silicon only.
- Use Xcode / `xcodebuild`, **not** `swift build` — MLX Swift compiles Metal shaders.
- The Metal toolchain is a separate Xcode component. On a machine without it, any build that
  recompiles MLX shaders fails with `cannot execute tool 'metal'`. Fix:
  `xcodebuild -downloadComponent MetalToolchain`.
- The project is generated by XcodeGen: `xcodegen generate` → `open Dictum.xcodeproj`.
  Edit `project.yml`, never the `.xcodeproj`.
- App is non-sandboxed by design: CGEvent tap, AXUIElement, pasteboard access, audio capture.
- Code signing is manual and requires local configuration.

### Dependency pins worth knowing

- `mlx-swift` 0.31.5+ adds an `Encuda` target and a `CudaBuild` build plugin. The plugin needs
  interactive trust (breaks CI) and `Encuda` does not compile under the current toolchain.
- `swift-transformers` is held at 1.1.x. Version 1.2.0 removes the `Downloader` protocol and
  repoints `HubApi` at `swift-huggingface`, which is exactly what the `HubDownloader` bridge in
  `LLMProcessor.swift` is built on. It is only needed for that MLX bridge — WhisperKit vendors
  its own copy of Hub and Tokenizers since 1.0.0.
- WhisperKit lives at `argmaxinc/argmax-oss-swift` since 1.0.0; the `WhisperKit` library product
  survived the rename, so the import stays the same.

## Architecture

- Layered macOS utility app, not DDD.
- `DictationPipeline.swift` orchestrates recording, transcription, optional LLM cleanup, and
  paste / clipboard output.
- Modules: `Audio/`, `Transcription/`, `TextProcessing/`, `Context/`, `ModelBrowser/`,
  `FloatingIndicator/`, `MenuBar/`, `HotkeyAndPaste/`, `Settings/`.
- `TranscriptionEngine` and `LLMProcessor` are actors. Both dedupe concurrent loads *per model
  id* — joining an in-flight load for a different model would silently hand back the wrong one.
- The target builds in **Swift 6 language mode**. Two deliberate escape hatches remain, both in
  `AudioRecorder`: `@preconcurrency import AVFoundation` (tap and converter callbacks are
  `@Sendable` but vend non-Sendable buffers) and `@unchecked Sendable` on the class itself, whose
  invariants are documented at the declaration. `Timer` callbacks must not capture their `Timer`
  argument — it is not Sendable, so reaching it from a main-actor body is a cross-isolation send;
  invalidate through the stored property instead.
- Models load lazily and are warmed up after load.
- Context mode (something was selected when dictation started) copies the result to the
  clipboard instead of auto-pasting.

## Key Gotchas

- Default hotkey is Right Command, in modifier-only mode.
- Accessibility permission is mandatory and cannot be auto-granted.
- **The CGEvent tap callback must stay fast.** macOS disables a slow tap, which kills the hotkey
  until the tap is re-enabled (`handleEvent` does this on `.tapDisabledByTimeout`). Never do file
  I/O or blocking work on that path — this is why `dlog` writes asynchronously and why the
  per-`flagsChanged` logging was removed.
- `resolvePrompt(for:)` layers a per-app prompt, or the general prompt, on top of the unified
  system prompt. It always returns a non-empty prompt; LLM cleanup is skipped only when
  `llmCleanupEnabled` is off.
- Settings use plain computed properties over `UserDefaults`, not `@AppStorage`: `@AppStorage`
  inside an `ObservableObject` only publishes when written through a SwiftUI binding, so writes
  from elsewhere in the app would not refresh the UI.
- Launch-at-login fails from DerivedData; it only works from an installed app in `/Applications`.
- Uninstall removes the shared MLX cache root, not only Dictum-owned models.
- Screenshot context uses the PID captured when recording *started*, not whatever is frontmost
  when the screenshot is finally taken.

## Conventions

- UI language: Polish, in `.strings` files only.
- Code, comments, docs, changelog, and commits: English only.
- `.strings` files contain Polish characters — never write them with a plain text-writing tool
  that may mangle the encoding.
- No transcription history is stored, and `dlog` must not log dictated text or LLM output —
  log lengths, not contents.
- `LSUIElement = true`, so the app has no Dock icon.
- Menu bar icon states are driven from `AppState`.

## Dev Cycle

- After code changes: `pkill -x Dictum` → `xcodebuild -project Dictum.xcodeproj -scheme Dictum`
  → launch the new build.
- No PR-based workflow; validate locally before committing to `main`.
- Run SwiftLint and SwiftFormat before committing if they are installed locally.

## Debugging

- `dlog()` writes to `~/Library/Logs/Dictum/dictum.log` (1 MB, one `.bak` rotation).
- `tail -f ~/Library/Logs/Dictum/dictum.log` for pipeline debugging.

## Tests

- No tests right now; manual QA only.
- Do not add XCTest without asking.

## Release

- Manual flow: bump `MARKETING_VERSION` in `project.yml` → update `CHANGELOG.md` → tag → push
  with tags.
- `release.yml` builds and publishes the app; `pages.yml` deploys `website/`.
- Release secrets: `CERTIFICATE_P12`, `CERTIFICATE_PASSWORD`, `SPARKLE_EDDSA_KEY`.
